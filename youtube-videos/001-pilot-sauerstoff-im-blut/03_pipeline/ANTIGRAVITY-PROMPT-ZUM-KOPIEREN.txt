# ANTIGRAVITY – PILOT 001 „SAUERSTOFF VON DER LUNGE BIS ZUR ZELLE“

Arbeite ausschließlich technisch nach dem Repository.

Projekt:

```text
youtube-videos/001-pilot-sauerstoff-im-blut/
```

## Ziel

Erzeuge aus Voice + finalen Flow-Bildern einen schnellen, klaren Object-Talk-Erklärfilm.

Der Film soll wie eine moderne animierte Erklärserie wirken und NICHT wie eine Diashow.

## Verbindliche Bildwelt

Autoritativ:

```text
bildwelt/OBJECT-TALK-CHANNEL-DNA.md
bildwelt/EXPLAINER-STYLE-LOCK.md
engine/FLOW-PRODUCTION-STANDARD.md
```

Explainer-Szenen:
- moderne stilisierte 2.5D / Soft-3D Educational Illustration
- ca. 80 % animierte Illustration / 20 % Soft-3D-Tiefe
- hell, klar, anschaulich
- kein Medical-CGI / Photorealismus
- biologische Strukturen normalerweise gesichtslos
- semantische Farben aus dem Repo beibehalten

## AUDIO IST ZUERST ZU KORRIGIEREN

Das rohe TTS-Audio darf NICHT direkt in die Timeline oder in den Render.

Zuerst zwingend:

```bash
python tools/prepare_audio.py \
  youtube-videos/001-pilot-sauerstoff-im-blut/01_script/audio/RAW_AUDIO \
  youtube-videos/001-pilot-sauerstoff-im-blut/01_script/audio/final-voiceover.wav \
  --speed 1.10
```

Verbindlich:
- Voice-Geschwindigkeit = 1.10x
- lange interne TTS-Pausen werden komprimiert
- kurze natürliche Mikro-Pausen bleiben erhalten
- `final-voiceover.wav` ist danach die EINZIGE Timing-Quelle
- Whisper wird auf `final-voiceover.wav` ausgeführt, nicht auf dem Roh-Audio
- Timeline wird NACH der Audioaufbereitung neu gebaut
- niemals eine 1.00x-Timeline bauen und später nur das Audio beschleunigen

## RHYTHMUS / KEINE LANGEN PAUSEN

- Voice steht fast durchgehend im Fluss
- kein künstliches Warten zwischen Sätzen
- keine leeren Standbild-Holds zur Laufzeitverlängerung
- ein normales Standbild meistens 3–6 Sekunden
- harte Obergrenze pro Bild: 7 Sekunden
- wenn ein Speech-Abschnitt länger ist, muss er in mehrere EINDEUTIGE Szenen/Bilder geteilt werden
- dasselbe Bild darf nicht zweimal als Ersatz für fehlende visuelle Dichte verwendet werden
- letzter Shot endet eng am Voiceover, kein langer Outro-Hold

## BILDER / ASSET-HYGIENE

Jede finale Bildnummer existiert genau einmal.

Verboten:
- dasselbe Bild zweimal in der Timeline verwenden
- `Bild_12` an zwei verschiedenen Stellen wiederholen
- alternative Normal-Szenen im finalen Ordner behalten
- `v2`, `final2`, `copy`, `_A`, `_B` im finalen Set

Cover-Ausnahme:
- nur `Bild_01` darf vor Auswahl bis zu 3 Varianten haben
- nach Nutzerwahl genau 1 Cover behalten
- alle anderen Cover-Kandidaten löschen/verwerfen

## SICHTBARER TEXT

Interne Produktionsnamen dürfen nie sichtbar sein.

Hard FAIL im Bild:
- `Bild 19`
- `Bild_19`
- `BILD_12 – O2 BINDET`
- `Scene 19`
- `IMAGE 19`
- Dateinamen / Asset-IDs / Prompt-Ueberschriften

Sichtbarer Text ist Whitelist-basiert:
- Cover: nur exakte Hook
- normale Szene: nur exakt geplante Labels
- wenn Szene 0 Labels hat, darf kein Wort sichtbar sein
- keine erfundenen Titel oder Extra-Erklärsätze

## INFORMATIONS-DICHTE

Nicht jedes Bild muss extrem leer sein.

Standard:
- ein dominanter Lehrpunkt
- 1–2 Hauptobjekte
- wenige Labels

Bei ca. 20–30 % der wichtigen Mechanismus-/Zusammenfassungsbilder darf EIN zusätzlicher sinnvoller Detailpunkt vorkommen, z. B. Zielobjekt, Vorher/Nachher-Cue oder kleines Detailfenster.

Wenn mehr Information nötig ist, bevorzuge ein zusätzliches eindeutiges Bild statt Textwand oder überladener Szene.

## SCHNITTPRINZIP

Die Reise bleibt logisch:

```text
Einatmen
→ Atemwege
→ Lunge
→ Alveole
→ Blut
→ rotes Blutkörperchen / Hämoglobin
→ Herz
→ Arterien
→ Kapillare
→ Muskelzelle
→ Mitochondrium
→ CO₂ zurück zur Lunge
```

Kontinuität entsteht über:
- gleiche O₂-/CO₂-Farben
- gleiche Blutkörperchen
- gleiche Stil- und Formlogik
- sinnvolle Bewegungsrichtung
- klare Makro→Mikro-Übergänge

Übergänge:
- harte saubere Schnitte sind Standard
- kurze weiche Überblendung nur bei echtem Maßstabs-/Ortswechsel
- keine dekorativen Meme-/Glitch-Transitions

## KAMERABEWEGUNG

- Push/Pull ca. 2–4 %
- Pan ca. 20–30 px bei 1080p
- weiche Ease-in/Ease-out-Bewegung
- Bewegung entlang des erklärten Prozesses
- keine aggressiven Ken-Burns-Zooms
- kein Shake / Bounce

## COVER

`Bild_01` ist Cover + erster Shot + Style-Anker.

- keinen zweiten Titel darüberlegen
- Hook vollständig sichtbar lassen
- Covermotiv nicht anschneiden
- nur dezenter Start-Push
- keine Zusatzlabels
- keine interne Bildnummer

## VORBEREITUNG

Vom Repo-Root:

```bash
python -m pip install -r tools/requirements.txt
python tools/validate_planning_v2.py youtube-videos/001-pilot-sauerstoff-im-blut
python tools/prepare_phase3.py youtube-videos/001-pilot-sauerstoff-im-blut
```

`prepare_phase3.py` muss:
1. finale eindeutige Bilder importieren
2. `final-voiceover.wav` als kanonisches Audio verwenden
3. Whisper-Worttimings aus dem verarbeiteten Audio erzeugen
4. Script strikt gegen Audio ausrichten
5. Timeline neu aus echten Worttimings bauen
6. bei einer Szene >7s FAIL melden statt sie lang stehen zu lassen
7. Renderer-Runtime inkl. Overlays vorbereiten

## OVERLAYS

- vorhandene korrekte Flow-Labels nicht unnötig doppeln
- falsches/unlesbares Flow-Label exakt in Remotion ersetzen
- zusätzliche Overlays nur an echten Story-Beats
- keine Captions / kompletten Voiceover-Sätze
- keine großen UI-Karten
- Anatomie/Hauptprozess nicht verdecken
- lieber kurze Schlagwörter als Erklärabsätze

## FINAL-QA

```bash
python tools/qa_final.py \
  youtube-videos/001-pilot-sauerstoff-im-blut/04_export/fertiges-video/final-video.mp4 \
  youtube-videos/001-pilot-sauerstoff-im-blut/01_script/audio/final-voiceover.wav \
  --min-seconds 100 \
  --expected-speed 1.10 \
  --max-voice-pause 0.50
```

Besonders prüfen:
- Voice-Speed wirklich 1.10x
- keine lange stille Voice-Pause >=0.50s
- kein einzelnes Bild >7s
- kein Bildasset doppelt in der Timeline
- finale Bilddateien jede Nummer exakt einmal
- keine sichtbaren Asset-/Szenennummern oder Prompt-Titel
- sichtbarer Text nur aus der Whitelist
- Cover nur einmal und nur mit Titel
- alle Szenen in derselben 2.5D/Soft-3D-Welt
- O₂/CO₂/RBC/Hämoglobin konsistent
- keine medizinische/fotorealistische Drift
- letzte Szene endet eng mit dem Voiceover

Bei Konflikt: FAIL statt raten.
