ANTIGRAVITY – PILOT 002 „WAS PASSIERT MIT ZUCKER IN DEINEM KÖRPER?“

Arbeite ausschließlich nach dem Repository.

Projekt:
`youtube-videos/002-zucker-im-koerper/`

ZIEL
Erzeuge aus Voice + 35 finalen Flow-Bildern einen schnellen, klaren animierten Erklärfilm. Kein Diashow-Gefühl.

AUDIO ZUERST
- Roh-TTS niemals direkt rendern.
- `tools/prepare_audio.py` mit `--speed 1.10` verwenden.
- lange TTS-Pausen vor Whisper/Timeline komprimieren.
- `final-voiceover.wav` ist die einzige Timing-Quelle.
- niemals eine 1.00x-Timeline bauen und später nur Audio beschleunigen.

BILDREGELN
- exakt 35 eindeutige finale Bilder: Bild_01 bis Bild_35.
- dasselbe Bild nie zweimal in der Timeline verwenden.
- kein Bild länger als 7 Sekunden stehen lassen.
- normale Bilder: genau ein retained asset pro Nummer.
- nur Cover darf vor Auswahl bis zu 3 Varianten haben; danach nur eine behalten.
- Finale Bild_35 ist eine neue Zusammenfassung, nicht das Cover wiederverwenden.
- nicht mehr als zwei isolierte Einzelobjektbilder direkt hintereinander; danach bevorzugt Prozess/Weg/Ursache-Wirkung/Kontext.
- ähnliche Übersichtsbilder müssen einen neuen visuellen Zweck oder deutlich andere Komposition haben.

COVER-HOOK – NUR EINMAL
Die exakte Hook `So verarbeitet dein Körper Zucker` darf im gesamten Video nur auf Bild_01 sichtbar sein.

Für Bild_02–Bild_35:
- Hook nie wieder anzeigen
- weder als große Überschrift noch als Kapiteltrenner
- keine verkürzte nahezu identische Wiederholung
- wenn sie in einem Flow-Bild sichtbar ist: Bild ist FAIL und muss ersetzt werden

SICHTBARER TEXT
- strikt nach `02_bildprompts/label-plan.json`.
- interne Nummern/Dateinamen/Prompttitel nie sichtbar.
- Hard FAIL bei `Bild_19`, `BILD_19`, `Scene 19`, Dateiname oder erfundenem Szenentitel.
- keine Captions oder langen Voiceover-Sätze als Overlay.
- zusätzliche Kapitelhinweise ausschließlich aus `03_pipeline/overlay-plan.json`.
- Overlay-Texte nie durch die Cover-Hook ersetzen oder mit ihr ergänzen.

REFERENZREGEL
- normale Szenen sollen auf einer TEXTFREIEN Style-Referenz basieren.
- texttragendes Bild_01 nicht als Referenz für Bild_02+ verwenden.
- Style-Referenz liefert Stil/Farben/Formensprache, nicht Typografie oder Cover-Komposition.

BILDWELT
- moderne stilisierte 2.5D / Soft-3D Educational Illustration.
- ca. 80% animierte Illustration / 20% Soft-3D-Tiefe.
- kein Photorealismus / Medical-CGI.
- hell, freundlich, klare Formen.

SEMANTISCHE FARBEN
- Glukose = Türkis/Cyan + warmer Goldakzent
- Insulin = Blau
- Glukagon = Violett
- Gefäße = Coral-Rot
- Glykogen = Amber/Gold
- ATP = Gelb/Gold

SCHNITT
- harte saubere Schnitte Standard.
- weiche Überblendung nur bei echtem Maßstabs-/Ortswechsel.
- Push/Pull 2–4%, Pan 20–30 px.
- keine aggressiven Ken-Burns, kein Shake, Bounce, Meme-Transition.
- Bewegungsrichtung unterstützt den Prozess.

STORY-REISE
Nahrung → Mund/Magen → Dünndarm → Glukose → Blut/Pfortader → Leber → Bauchspeicheldrüse/Insulin → Zellaufnahme → ATP → Glykogen → langfristiger Energieüberschuss/Fett → Glukagon → Leber gibt Glukose frei → Zusammenfassung.

INFORMATIONSDICHTE
- ein dominanter Lehrpunkt pro Frame.
- bei etwa 20–35% wichtiger Mechanismusbilder darf ein sinnvoller Zusatzdetailpunkt vorkommen.
- wenn ein Mechanismus zwei echte Schritte enthält, lieber zusätzliches eindeutiges Bild als Textwand.
- wichtige Story-Beats dürfen die kurzen einzigartigen Kapitel-Overlays aus `overlay-plan.json` nutzen.

VORBEREITUNG

python tools/prepare_phase3.py youtube-videos/002-zucker-im-koerper
```

RENDER

npm install

```

FINAL-QA
```bash
python tools/qa_final.py \
  youtube-videos/002-zucker-im-koerper/04_export/fertiges-video/final-video.mp4 \
  youtube-videos/002-zucker-im-koerper/01_script/audio/final-voiceover.wav \
  --min-seconds 100 \
  --expected-speed 1.10 \
  --max-voice-pause 0.50
```

Manuell zusätzlich prüfen:
- Cover-Hook nur auf Bild_01
- keine Hook-Wiederholung in normalen Bildern oder Overlays
- keine drei nahezu identischen Einzelobjekt-Portraits am Stück
- Bild_30 und Bild_33 klar unterschiedlich komponiert
- finale Zusammenfassung Bild_35 ist neu und nicht coverartig kopiert

Bei Konflikt oder fehlenden Assets: FAIL statt raten.
